## T67a — `fit_head` reserves the cursor before spending the rest top-down

`anchor_inject.py::fit_head` today spends the budget in pure document order
("Document order IS the drop order"), so a HEAD whose Cursor sits below a
standing-directives block loses the one section a resuming session cannot do
without. Four post-fix reports in nine days.

Shape: `fit_head` finds the cursor section with the same matcher
`anchor_cursor` already uses, reserves its cost, spends the remaining budget
top-down over the other sections in document order, and re-assembles the kept
sections **in document order** so the reserve changes what survives, not where
it appears. When the cursor alone overruns the budget, it is kept and cut and
everything else is named as dropped.

The return value becomes a named tuple (`text`, `dropped`, `byte_cut`,
`cursor_reserved`) so `build_context` can say the cursor was reserved in the
drop line rather than leaving a reader to infer it.

## T67b — `--head-fit` CLI arm

The hook computes the fit on every injection; the author has no way to ask for
it and hand-wrote the byte counter three times in one session, shipping a head
118 bytes over budget. New arm `anchor_inject.py --head-fit <anchor>` prints
head bytes, the budget, the cursor section it reserved, and which sections
would drop at the current size. It reports and exits 0, like `--list-stale`
and `--list-dormant` — it is a measuring arm, not a gate, which keeps
`anchor_inject.py`'s red-proof exemption ("every path exits 0") true.

Named from `compaction-survival/SKILL.md` protocol step 5 and `/anchor` step 4.

## T67d — a file in `anchors/` is injected only when it is shaped like an anchor

A 79 KB design document was injected as the anchor. `select_anchor` gains a
shape predicate — `format: anchor/...` frontmatter, or a section whose heading
names a cursor — and de-ranks a file that has neither below every anchor-shaped
candidate, exactly as it already de-ranks a content-terminal one. The warning
line names such a file as "not an anchor". Nothing is refused outright:
injecting zero bytes on the recovery path is the protocol's cardinal failure.

## T68a — a `PreToolUse` hook at the spawn surface

`choosing-models` took zero invocations across a 139-agent, 40-hour programme
under a written owner order repeated three times. The skill has no trigger at
the moment it governs. New hook, `skills/choosing-models/scripts/
inject_spawn_routing.py`, wired at `PreToolUse` on the spawn tool, reusing
`inject_dispatch.py`'s contract: stdlib only, ASCII-only output, fail open on
every path, telemetry best-effort.

Two silences keep it from becoming noise:

- a spawn that already names a `model` has been routed — say nothing;
- at most one hint per session per cooldown window, so a 54-item fan-out is
  reminded once at the script rather than once per agent.

The block names the activation test and the batch counter-rule and points at
the skill. It does **not** restate the thresholds: `models.toml` owns them, and
a second copy in a hook is the drift class this corpus already pays for.

Ships on; `HUMBLEPOWERS_SPAWN_ROUTING_HINT=0` is the opt-out, matching the
polarity `scripts/check_gate_claims.py` reads out of the guard.

## T70a — `plugin_version.py` names every installed copy

Several versions of one plugin coexist in the cache and the oldest can serve;
the condition is live for three of the four plugins in this marketplace. The
resolved install path's last segment is the version, so its parent is the
directory holding every installed copy: one `glob`. `field_line` gains a
"N copies installed" clause when more than one is present, so a report's
version attribution carries the ambiguity instead of hiding it.

## T70c — the same fact in the session-start inventory

`scan_toolkit.py` gains a caveat naming any plugin with more than one installed
copy, alongside the installed-vs-source and stale-checkout caveats it already
emits. The inventory is read at session start; an on-demand command is not.

Note on fidelity: the triage row asks for "the serving-versus-installed line
the version script already computes". No script in the tree computes a
serving-versus-installed line outside `--check-serving`, which needs a
transcript the ordinary scan does not have. What is implemented is the
multi-copy fact at the surface the row names.
