# LLM signature — trailer spec (llm-signature/v1)

The signature is a pair of [git trailers](https://git-scm.com/docs/git-interpret-trailers)
recording the provenance of agent-assisted work. It is generated by
`scripts/render_signature.py` from live sources; a hand-typed signature is a
spec violation (it rots, and wrong provenance is worse than none).

## Grammar

```text
Assisted-By: <model-id>
Agent-Stack: <item>[; <item>]...

item     := <name>[@<version>][ (<marketplace>)]
model-id := the exact model identifier, e.g. claude-sonnet-5, claude-opus-4-8
```

One line per trailer (no continuations), emitted as the final paragraph of the
commit message so git parses them as one trailer block. Example:

```text
feat(pipeline): add schema-drift gate

Assisted-By: claude-sonnet-5
Agent-Stack: claude-code@2.1.211; engineering-discipline@2.1.0 (craft-collection); session-workflow@0.15.0 (craft-collection)
```

## Semantics

- **`Assisted-By` is singular and carries responsibility.** It names the model
  that wrote and orchestrated the change — the one accountable for it. Models a
  session merely delegated to (subagents, sidechains) are not listed; if the
  orchestrating model changed mid-session, the one at commit time signs. The
  model never appears as a `Co-Authored-By`, author, or committer.
- **`Agent-Stack` is selective.** Harness first (`claude-code@<version>`), then
  enabled plugins sorted by name. Disabled plugins are excluded; `--plugin`
  narrows further when only part of the stack shaped the work. If nothing
  resolves, the trailer is omitted — an empty stack line carries no information.
- **The marketplace label is a reference, not a URL.** `(craft-collection)`
  resolves via `claude plugin marketplace list` or the adopting repo's
  README/resolution table. Commits carry short stable keys; the repo carries
  the mapping to marketplace pages.
- **Human co-authorship is untouched.** `Co-Authored-By` lines naming people
  are preserved everywhere; only lines naming the agent vendor (claude /
  anthropic) are treated as boilerplate the signature replaces.

## Resolution sources (why it is never hand-typed)

| Field | Source | Notes |
|-------|--------|-------|
| model | session transcript, last main-loop `assistant` message | `--model` / `--transcript` override; auto-discovery matches the munged cwd under `~/.claude/projects/` and requires a live session (`CLAUDECODE` set) so a stale transcript never signs |
| harness | `claude --version` | omit with `--no-harness` |
| plugins | `claude plugin list --json` | enabled only; `id` = `plugin@marketplace` |

Failure is loud in render mode (exit 1, nothing printed) and safe in `--apply`
mode (scrub-only, exit 0): a signing problem must never invent provenance or
block a commit.

## Reading signatures back

```bash
git log --format='%h %(trailers:key=Assisted-By,valueonly)'          # who signed what
git log --grep='Agent-Stack: .*session-workflow@0\.14' --oneline     # work shaped by a given version
git interpret-trailers --parse < msg                                  # machine parsing
```

## Optional git hook (full mechanical enforcement)

`--apply` is idempotent (refreshes, never duplicates) and commit-safe, so it
can run as a `prepare-commit-msg` hook. `${CLAUDE_PLUGIN_ROOT}` does not exist
in git's environment — substitute the installed plugin path (shown by
`claude plugin list` as `installPath`):

```bash
# .git/hooks/prepare-commit-msg  (chmod +x)
#!/bin/sh
uv run --no-project -- python "<installPath>/skills/llm-signature/scripts/render_signature.py" --apply "$1"
```

Outside a live agent session the hook scrubs boilerplate but signs nothing
(no `CLAUDECODE` in the environment means the newest transcript belongs to a
previous session — signing from it would attribute the wrong model). Human
commits therefore pass through unsigned, which is the intended behavior.

## Versioning

This is `llm-signature/v1`. Additive fields (e.g. MCP servers in
`Agent-Stack`) may arrive without a version bump; a change to the meaning of
an existing trailer requires `v2` and a spec note here.
